# Pet Care Tracker

Уеб приложение на Django за водене на дневник на грижите за домашни любимци. Записваш любимците си със снимка, слагаш им етикети („алергичен“, „на диета“) и водиш история на храненията, ваксините, разходките и прегледите.

Индивидуален проект за изпита по **Django Basics** в SoftUni.

## Функционалности

- **Любимци** с пълен CRUD: добавяне, списък, детайли, редакция, изтриване с потвърждение.
- **Снимка по избор:** линк към снимка от интернет **или** качване на файл от компютъра/телефона.
- **Филтриране** на любимците по вид (напр. само кучетата).
- **Дневник на грижите** с пълен CRUD. Всеки запис е свързан с любимец; най-новите са най-отгоре.
- **Етикети** с връзка много-към-много с любимците.
- **Профил на любимец** с всичките му записи от дневника.
- **Две теми:** тъмна и светла, с бутон за смяна в менюто.
- **Адаптивен дизайн** за компютър, таблет и телефон.
- Собствена страница за **404**.

## Инсталация и стартиране

### 1. Изтегляне

```bash
git clone https://github.com/plamenivanovofficial-code/pet_care_tracker.git
cd pet_care_tracker
```

### 2. Виртуална среда

**Windows (PowerShell):**
```powershell
python -m venv venv
venv\Scripts\activate
```

**macOS / Linux:**
```bash
python3 -m venv venv
source venv/bin/activate
```

### 3. Зависимости

```bash
pip install -r requirements.txt
```

### 4. База данни

```bash
python manage.py migrate
```

Създава празна SQLite база (`db.sqlite3`). Не са нужни начални данни, всичко се създава от сайта.

### 5. Стартиране

```bash
python manage.py runserver
```

Отвори **http://127.0.0.1:8000/**

### Препоръчителен ред за първи тест

1. **Добави → Етикет**: създай 1–2 етикета (по желание).
2. **Добави → Любимец**: попълни данните, сложи линк или качи снимка, избери етикети.
3. **Добави → Запис в дневника**: избери любимеца и дата.
4. Отвори любимеца от **Любимци**. Ще видиш профила и дневника му.

> Записът в дневника изисква поне един любимец. Ако няма, формата показва съобщение с линк към добавяне.

## Променливи на средата

**Не са нужни.** Проектът работи с настройките по подразбиране след `migrate`.

| Настройка | Стойност | Бележка |
|---|---|---|
| `DEBUG` | `True` | за локално тестване |
| `SECRET_KEY` | в `settings.py` | само за разработка |
| `DATABASES` | SQLite, `db.sqlite3` | създава се от `migrate` |
| `MEDIA_ROOT` | `media/` | качените снимки; папката се създава сама |
| `LANGUAGE_CODE` | `bg` | вградените съобщения и датите са на български |

### Как да видиш страницата за 404

При `DEBUG = True` Django показва своята техническа страница за грешка. За да видиш собствената 404 страница, в `pet_care_tracker/settings.py` временно смени:

```python
DEBUG = False
ALLOWED_HOSTS = ['127.0.0.1', 'localhost']
```

и отвори несъществуващ адрес, напр. `/pets/9999/`.

> При `DEBUG = False` Django не сервира статичните файлове и снимките, затова стиловете няма да се заредят. Това е нормално поведение и е само за проверка на 404.

## База данни

```
┌──────────┐        ┌──────────────┐        ┌───────────────┐
│   Tag    │ M ── M │     Pet      │ 1 ── M │ CareActivity  │
└──────────┘        └──────────────┘        └───────────────┘
```

### `Tag` (pets)
| Поле | Тип | Бележка |
|---|---|---|
| `name` | `CharField(20)` | уникално |

### `Pet` (pets)
| Поле | Тип | Бележка |
|---|---|---|
| `name` | `CharField(30)` | |
| `category` | `CharField(30)` | вид, напр. „Куче“ |
| `age` | `PositiveIntegerField` | |
| `photo_url` | `URLField` | незадължително |
| `photo_file` | `ImageField` | незадължително, в `media/pets/` |
| `description` | `TextField` | незадължително |
| `tags` | `ManyToManyField(Tag)` | **много-към-много**, `related_name='pets'` |

- `Meta.ordering = ['name']`
- `@property photo` връща качения файл, ако има такъв, иначе линка. Шаблоните не се интересуват откъде идва снимката.

### `CareActivity` (care_logs)
| Поле | Тип | Бележка |
|---|---|---|
| `name` | `CharField(30)` | вид грижа, напр. „Ваксина“ |
| `date` | `DateField` | |
| `description` | `TextField` | незадължително |
| `pet` | `ForeignKey(Pet)` | **много-към-едно**, `CASCADE`, `related_name='care_activities'` |

- `Meta.ordering = ['-date']`: най-новите първи.

## Страници

Всички страници са достъпни от менюто горе (`Начало`, `Любимци`, `Дневник`, `Етикети`, `Добави`) и от footer-а.

| Адрес | Страница | Изглед |
|---|---|---|
| `/` | Начална: обобщение, любимци, последни грижи | `index` (FBV) |
| `/pets/` | Всички любимци + филтър по вид (`?category=`) | `PetListView` |
| `/pets/add/` | Нов любимец | `PetCreateView` |
| `/pets/<id>/` | Профил на любимец + неговия дневник | `PetDetailView` |
| `/pets/<id>/edit/` | Редакция на любимец | `PetUpdateView` |
| `/pets/<id>/delete/` | Потвърждение за изтриване | `PetDeleteView` |
| `/pets/tags/` | Всички етикети и любимците с тях | `TagListView` |
| `/pets/tags/add/` | Нов етикет | `TagCreateView` |
| `/care/` | Дневник на грижите | `CareActivityListView` |
| `/care/add/` | Нов запис | `CareActivityCreateView` |
| `/care/<id>/` | Детайли за запис | `CareActivityDetailView` |
| `/care/<id>/edit/` | Редакция на запис | `CareActivityUpdateView` |
| `/care/<id>/delete/` | Потвърждение за изтриване | `CareActivityDeleteView` |

**Пълен CRUD:** `Pet` и `CareActivity`. **Частичен:** `Tag` (създаване и списък).

### Шаблони
- **Наследяване:** всички страници наследяват `common/base.html`.
- **Преизползваеми partials:** `navbar.html`, `footer.html`, `form_fields.html` (рисува всяка форма с labels, грешки и помощни текстове), `pet_card.html`, `activity_row.html`.
- **Един шаблон за създаване и редакция:** `add_pet.html` и `activity_form.html` сменят заглавието и бутоните според това дали има `object`.
- **Вградени филтри и тагове:** `pluralize`, `truncatewords`, `timesince`, `date`, `slice`, `first`, `default`, `linebreaksbr`, `capfirst`, `urlencode`, `{% with %}`, `{% include ... with %}`, `{% now %}`, `{% empty %}`.

## Форми и валидация

| Форма | Модел | Валидации |
|---|---|---|
| `PetForm` | `Pet` | `clean_age`: не повече от 50 години; `clean_category`: почиства и уеднаквява („ кУЧЕ “ → „Куче“); `clean()`: изисква **линк или файл** за снимка |
| `PetDeleteForm` | `Pet` | наследява `PetForm`; **всички полета са само за четене** (`disabled`) |
| `TagForm` | `Tag` | `clean_name`: малки букви и без интервали; съобщение при дубликат (`unique`) |
| `CareActivityForm` | `CareActivity` | `clean_date`: датата не може да е в бъдещето |

Формите имат персонализирани `labels`, `placeholder`-и и `error_messages` на български, а `PetForm` и помощни текстове (`help_texts`). Изтриването винаги минава през страница за потвърждение. След успешно записване изгледите пренасочват (`success_url` / `get_success_url`).

## Допълнителни функционалности

- **Снимка чрез линк или качване** с проверка между две полета във формата (`clean()`) и `@property` в модела, който избира източника.
- **Филтриране** чрез презаписан `get_queryset()` в `PetListView`.
- **Изтриване със заключена форма:** `PetDeleteForm` наследява `PetForm` и заключва полетата в `__init__`; `PetDeleteView` подава обекта чрез `get_form_kwargs()`.
- **Тъмна и светла тема** с превключвател; изборът се пази в браузъра (`localStorage`).
- **Локални ресурси:** Bootstrap и шрифтовете са в `static/`, без зависимост от външни CDN.
- **Достъпност:** видим фокус при навигация с клавиатура, `aria` атрибути в менюто, уважава системната настройка „намалено движение“.

## Сигурност

- **XSS:** всички данни от потребителя се показват през `{{ ... }}`, което Django екранира автоматично. Никъде не се ползва `|safe`.
- **Линкове към снимки:** `URLField` приема само `http`/`https`, така че линкове от вида `javascript:` се отказват.
- **Качени файлове:** `ImageField` проверява с Pillow, че файлът е истинско изображение.
- **CSRF:** всички POST форми съдържат `{% csrf_token %}`.
